GameBoost BETA 测试版

开游戏前冻结后台进程，玩完一键精确还原 —— Windows 10/11 开源、零依赖、纯 PowerShell + 图形界面。

在 GitHub 查看 / Download 反馈问题 / Report an issue
⚠️ 这是测试版：它确实会挂起你的进程，请先读文档、用 -DryRun 试跑。发现"误冻结 / 漏冻结 / 恢复不完整"等情况，非常欢迎开 Issue。

它解决什么问题

浏览器、聊天工具、同步盘、厂商控制台会在你打游戏时继续占用 CPU 时间片、物理内存与磁盘 I/O。 GameBoost 用 Windows 原生机制把它们冻结（不是杀掉——标签页、会话、文档状态全部保留）， 同时回收它们占用的物理内存；结束后按精确快照还原优先级、内存优先级与能效（EcoQoS）状态。

与改注册表 / 停服务 / 清缓存的"游戏加速器"不同，本项目的操作完全可逆，且全程留日志。

核心特性

  • 真冻结：NtSuspendProcess 挂起全部线程，CPU 占用归零
  • 回收内存：EmptyWorkingSet 把被冻进程的工作集交给系统
  • 精确还原：优先级 / 内存优先级 / EcoQoS 原值写回
  • 只恢复自己冻过的进程（pid + 进程名 + 启动时间戳指纹）
  • 四层保护：关键进程判定 + 反作弊/杀毒黑名单 + 自身进程链 + 前台全屏兜底
  • 零依赖：PowerShell 5.1 + 系统自带 WinForms，无需任何运行时
  • 自动兜底：游戏退出即恢复、或 N 分钟后自动恢复
  • 实测：18 个目标冻结 1.60 秒、恢复 1.08 秒
  • 表单化自动选择：档案（4 套内置策略）+ 规则表，🪄 一键勾选、筛选（F6）、记住上次勾选
  • 选择性恢复：只恢复指定进程名（-Only），其余继续冻结，全部处理完才归档

表单化自动选择：档案 + 规则表

每次开游戏前手点几十个进程太累，于是把「该冻谁」做成了可复用的表单：档案（profile）是一套策略， 规则表（rules）是判定规则。规则按顺序匹配、首个命中生效，动作分三种： 真冻结（suspend）、只降 QoS（idle，不断消息、不丢自动保存）、不处理（skip）。

内置档案策略
游戏前冻结内存大户；微信/QQ/同步盘走软模式；Steam/Epic 等启动器排除在外
极简只碰 500MB 以上的进程，其余不动
只降QoS零风险：全部走软模式，一个都不冻结
办公放宽保留编辑器/IDE，其余走软模式
# 按档案冻结（先 DryRun 看一眼，什么都不改）
.\pause-non-system-processes.ps1 -Profile '游戏前' -DryRun
.\pause-non-system-processes.ps1 -Profile '游戏前' -Yes

# 只恢复先不玩的那几个，其余继续冻着
.\resume-non-system-processes.ps1 -Only 'Weixin','chrome' -Yes

内存门槛按进程名聚合判定：同名字下所有进程的工作集求和后再比较， 所以浏览器/Electron 的一堆几 MB 小助手进程不会被逐个漏掉。规则表不能解除硬保护—— 反作弊、杀毒、系统关键进程、会话 0 服务永远不会进入自动选择；启动器在默认规则表里就是"不处理"。

快速开始

git clone https://github.com/GzxingR/gameboost.git
cd gameboost

# 1) 先看它打算动谁（不改任何东西）
.\pause-non-system-processes.ps1 -DryRun

# 2) 冻结（默认 Safe 白名单）
.\pause-non-system-processes.ps1 -Yes

# 3) 玩完恢复
.\resume-non-system-processes.ps1 -Yes

# 更省事的用法：内置档案 + 选择性恢复
.\pause-non-system-processes.ps1 -Profile '游戏前' -Yes
.\resume-non-system-processes.ps1 -Only 'Weixin','chrome' -Yes

想用图形界面：双击 GameBoost.GUI.cmd，或运行 Install-GameBoostShortcuts.ps1 生成桌面快捷方式与热键 （Ctrl+Alt+G 控制台 / Ctrl+Alt+P 暂停 / Ctrl+Alt+R 恢复）。

安全模型：为什么它不会把你的游戏冻住

层级作用
关键进程判定IsProcessCritical 判定系统关键进程后跳过（不单靠它：该方法对 System、lsass 返回 False，故需与名单互补）
名字黑名单（硬编码）系统组件 + 反作弊与杀毒（腾讯 ACE、EasyAntiCheat、BattlEye、Vanguard、Windows Defender 等），配置文件与命令行参数都无法解除。挂起反作弊会崩游戏甚至封号，挂起杀毒属于 EDR 明确监控的恶意行为特征
自身进程链脚本的祖先与后代绝不冻结；终端家族与 explorer.exe 默认保护
前台全屏兜底冻结瞬间拥有前台全屏窗口的进程强制排除

与同类工具的差异

工具定位与本项目的关系
Process Lasso（闭源）长期优先级/亲和性调节（ProBalance）不做冻结；可并存
Mem Reduct / WinMemoryCleaner（开源）内存回收（工作集/待机列表）只回收不冻结；本项目冻结后才回收，效果更实在
SceneShift（开源，TUI）终端界面的挂起/结束进程同类思路；本项目侧重保护名单、指纹校验、QoS 快照与自动恢复
任务管理器「效率模式」（系统自带）对单个进程降 EcoQoS本项目可批量做，并额外冻结 + 回收内存

给 AI 代理 / For AI agents

"该冻谁"在这个项目里是数据（档案 + 规则表）而不是代码，机器接口也是稳定的，所以很适合让 AI 来扩展：

  • AGENTS.md：仓库地图、永不可放宽的安全红线、PowerShell 5.1 / UTF-8 BOM 约定、扩展点速查与验证命令
  • docs/AI-EXTENDING.md：5 个高频扩展任务 + 可直接复制的提示词 + 每个任务的不变量与验证方式
  • llms.txt · llms-full.txt：给 LLM 抓取的摘要 / 可整篇喂入的机器可读说明
  • schemas/：-EmitJson 与 config.json 的 JSON Schema（schema: 1 是稳定契约）
  • examples/：可直接加载的规则表 / 档案示例，以及 agent-drive.ps1（只打印计划，加 -Execute 才动手）

常见问题

冻结后反而更慢 / 窗口卡住？

被挂起的窗口无法响应消息，Windows 会显示为无响应——这是冻结的固有现象，恢复即可。若介意，用 -Mode Idle（只降 QoS 不冻结）或 -SkipVisible（跳过有可见窗口的进程）。

我的游戏启动器（Steam / Epic）会被冻住吗？

默认不会：默认规则表把 Steam / Epic / Battle.net / EA Desktop / Ubisoft Connect / Riot / WeGame / GOG 判为 skip （游戏通常要由它们拉起）。确实想冻，在列表里手动勾选即可——显式勾选优先于规则表。

每次都要手点几十个进程吗？

不用：顶部选「档案」（内置 4 套策略）再点 🪄 自动选择（F7），按规则一键勾选后手动增减； 勾选会被记住（state\selection.json），下次扫描自动回勾。玩完还能用「恢复所选…」只恢复先不玩的那几个。

需要多大的磁盘空间？

冻结会把脏页写回页文件，因此磁盘可用空间很小时不建议大批量冻结（实测 2 GB 脏页会让页文件使用量增加约 2 GB）。

会不会被反作弊判定为作弊？

不会：本项目不读写游戏内存、不注入、不改文件，只是挂起你自己指定的进程；且反作弊进程本身在硬保护名单里，永远不被挂起。

支持 Windows 10 / ARM64 / PowerShell 7 吗？

仅在 Windows 11 + PowerShell 5.1 上做过完整实测；其它组合理论上可用但未验证，欢迎反馈。
